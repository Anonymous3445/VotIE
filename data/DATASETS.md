# VotIE Dataset Documentation

## Directory Overview

| Directory | Role | Status |
|-----------|------|--------|
| `citilink-dataset/` | Raw source annotations from the CitiLink corpus (hierarchical JSON per municipality) | Tracked — source of truth |
| `citilink-votie/` | **Training-ready dataset** — span JSONL with oversampling and structural metadata | Tracked — pre-generated, ready to use |
| `citilink-votie-lomo-splits/` | Leave-One-Municipality-Out (LOMO) splits | Generated locally (see Step 3 below) |

The raw source dataset (`citilink-dataset/`) is also publicly available at:
**https://rdm.inesctec.pt/dataset/cs-2025-007**

## citilink-votie — Training-Ready Dataset

Generated from `data/citilink-dataset/` by running Steps 1–2 below.
Pre-generated files are included in this repository.

### Transformations applied (in order)

1. **SUB-SUBJECT boundary normalisation** — strips leading articles (o/os/a/as) from SUB-SUBJECT span text and offsets. Affects 8 train / 5 dev / 3 test spans.

2. **SUB-SUBJECT → SUBJECT relabel** (train/dev/test main files only) — all SUB-SUBJECT spans are relabeled SUBJECT. Original SUB-SUBJECT labels are preserved in the companion gold files (`dev_gold_with_sub_subjects.jsonl`, `test_gold_with_sub_subjects.jsonl`).

3. **Voting-only filter** — segments without a VOTING anchor span have their `spans` list cleared to `[]` and are kept as negative examples.

4. **Minority-class oversampling ×4** (train split only, seed=42) — segments containing at least one span of type COUNT-BLANK, COUNT-FAVOR, or VOTING-METHOD are duplicated 4 times (Appendix B.5 of the paper).

5. **Multi-vote segment oversampling ×4** (train split only, seed=42) — segments with ≥2 distinct `event_id` values among their VOTING spans are duplicated 4 times. A segment qualifying for both receives both factors independently.

6. **Structural metadata** — `is_multi_vote` (bool) and `subject_span_lengths` (list of token counts) are added to every record for analysis.

### Output files

| File | Description |
|------|-------------|
| `train.jsonl` | Augmented training set (2,463 segments after oversampling) |
| `dev.jsonl` | Development set (553 segments, no augmentation) |
| `test.jsonl` | Test set (529 segments, no augmentation) — use for all final evaluations |
| `dev_gold_with_sub_subjects.jsonl` | Dev set with original SUB-SUBJECT labels preserved |
| `test_gold_with_sub_subjects.jsonl` | Test set with original SUB-SUBJECT labels preserved |
| `generation_summary.json` | Full per-split statistics and per-municipality breakdown |

```json
{

  "text": "...",
  "spans": [{"text": "...", "label": "VOTER-FAVOR", "start": 12, "end": 34, "event_id": 1}],
  "municipality": "M02",
  "document_id": "Campomaior_cm_023_2021-11-17",
  "subject_id": "Campomaior_cm_023_2021-11-17_2",
  "is_multi_vote": false,
  "subject_span_lengths": [8]

```

## citilink-votie-lomo-splits — LOMO Splits

Generated by `scripts/dataset_generation/create_lomo_splits_v6.py`. Not distributed (67 MB) — run Step 3 below to generate locally.

For each of the 6 municipalities (M01–M06), one split holds out that municipality as the test set and trains on the remaining five. Used for the Leave-One-Municipality-Out cross-domain evaluation.

Structure: `M01/ … M06/`, each containing `train.jsonl`, `dev.jsonl`, `test.jsonl`, `statistics.json`.

## Reproducing the datasets

```bash
# Step 1: Convert raw CitiLink annotations to span format
python scripts/dataset_generation/convert_new_citilink_to_spans.py
# Input:  data/citilink-dataset/
# Output: intermediate JSONL (not distributed)

# Step 2: Generate training-ready dataset (already distributed as data/citilink-votie/)
python scripts/dataset_generation/generate_v6_multi_vote_aware.py \
    --output-dir data/citilink-votie \
    --oversample-factor 4 \
    --multi-vote-oversample-factor 4 \
    --seed 42

# Step 3: Generate LOMO splits (needed for cross-municipality experiments)
python scripts/dataset_generation/create_lomo_splits_v6.py \
    --output-dir data/citilink-votie-lomo-splits
```
